Maths focus stage F.1: the skill engine. This is the first stage of the plan that decides what maths every game asks each student. It changes no database tables and nothing goes live.

Where things are:
- School Games Hub repo. Make a new worktree ~/projects/school-games-hub-focus on a new branch `maths-focus` from main (other sessions use the other checkouts, so don't work in them). Don't merge to main and don't deploy anything until I say "go live".
- Read docs/MATHS-FOCUS-PLAN.md first. It is the source of truth: section 3 (the skill ladder and the two kinds of skill), section 11 (stages, F.1 is first), section 12 (where the ladder order comes from, including the new times-table order and the NZC families), and section 10 (my answers). Then read shared/maths/skillPack.ts, shared/maths/selector.ts and shared/maths/config.ts, and how Gem Keep and Wormholes & Black Holes call them and send answers to `record_fact_answers`.
- The NZC 2025 Teaching Sequences are already extracted in ~/maths-alignment-tool/data/curriculum/teaching-sequence/ (stable IDs like `MS.Y5.NUM.RN.P15`). Fetch the latest alignment tool first, the local clone may be behind. Each skill's `curriculumTags` comes from there.

Build F.1:

1. **The ladder as a list in shared/maths/config.ts**, easiest first, in the order from section 3 and 12: early facts, times tables, place value, rounding, order of operations, fractions/decimals/percentages. All stages are listed now, but only the early facts and times tables get working generators in this stage; the later ones are stubs marked "not built yet" that auto skips. Changing the order must never need a code change.
2. **The new times-table order** from section 12, replacing today's `CAMPAIGN_STEPS`. Keep the `mul:6x7` fact keys exactly as they are so no student loses records. Say how a student who is partway through the old order lands in the new one.
3. **Generalised fact keys** (`bond10:3+7`, `bond20:8+12`, `dbl:7`, `half:14`, `mul:6x7`) with the Leitner boxes working the same way for every fact skill.
4. **The first new fact skills**: bonds to 10, bonds to 20, doubles to 10 + 10, halves of even numbers to 20, adding and subtracting within 20, and division facts. Each is a skill pack behind the existing `skillPack.ts` interface (`nextQuestion(ctx)` and `recordAnswer()`), with its `curriculumTags` filled in from the NZC IDs. Questions stay a single number answer, so the number pad and multiple choice keep working.
5. **Auto for the early part of the ladder**: `readyLevel()` generalised so it moves a student on when 70% of a step's facts are in box 2 or higher, with the same 60% focus, 30% review, 10% stretch mix. Weight review toward the hardest tables (6, 7, 8, 9, 12) as section 12 says.
6. **`ladderProgress(stats)`** (section 5b): a shared function giving the skill a student is on, which skills are secure, and how far through the ladder they are as a percentage, using the same 70% rule as auto. No screen yet, that is F.4.
7. **Generators live in `shared/`** so a server function can rebuild any question from its seed and mark it later.

Tests: every generator makes only valid questions with the right answer and sensible wrong choices, never repeats the same question twice in a row, and is the same for the same seed; every fact key round-trips; old `mul:` records still work and land in the right place in the new order; `readyLevel()` moves on and holds back correctly at the 70% line; review mixes follow the percentages over a large sample; every skill has at least one curriculum tag that exists in the extracted NZC data. Run the whole suite and the type check. Known failures to check and name: the two stale server bundles (`npm run build:functions` fixes them, say if you ran it), and the random tests (101 stats, chess bot, one Wormholes & Black Holes test) that can fail once when the machine is busy.
