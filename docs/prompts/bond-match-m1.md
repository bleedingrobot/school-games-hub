Build M.1: `shared/bond-match/`, pure TypeScript with no React, no browser APIs, no Math.random and no Date.now (the same inputs must always give the same game):
1. `bonds.ts`: the bond sets as data, so a new bond is one entry. Each has an id, a label, a shelf (whole numbers / decimals / fractions / mixed forms), a target, the list of possible pairs, and how each side of a card is shown (a plain number, a decimal with a fixed number of places, or a fraction with numerator and denominator, so the screen can draw a stacked fraction). Include every set in plan section 2: whole numbers to 10, to 20, to 100 (tens), to 100 (any), to 1000 (hundreds), to 1000 (tens); decimals to 1 (tenths), to 1 (hundredths), to 10 (tenths); fractions to 1 for halves, thirds, quarters, fifths, sixths, eighths, tenths. Leave "mixed denominators" and the "mixed forms" shelf (¼ and 0.75) for M.3, but make the data shape able to hold them (a card side can be any of the three kinds, and a pair is two sides that sum to the target).
2. `deck.ts`: build a deck from (bond set, board size, seed). Board sizes: Small 6 pairs, Medium 8 pairs, Large 10 pairs. Pairs are chosen with the seeded random. If the set has fewer distinct pairs than the board needs (bonds to 10 has 5), repeat pairs in a second colour set, never more than twice each. The deck must have exactly one partner for every card, and a pair that is two identical sides (5 and 5, ½ and ½) counts as one card matching its twin. Colour sets are part of the card, so a card only matches its own colour set's partner. Export a checker `partnersOf(deck)` that the tests use.
3. `engine.ts`: `flip(state, cardIndex) → { state, events }`, pure. Rules: first flip shows a card; second flip shows another; if they sum to the target AND are partners in the same colour set they match and stay up; otherwise they stay up until the next flip call turns them back (so the screen can show the "3 + 4 = 7" line first). Events say what happened: `first`, `match`, `mismatch` (with both values and their sum, as exact values, so decimals never show 0.30000000000000004), `finish`. Flipping a matched card, the same card twice, a third card while a mismatch is showing without first clearing it, or a card index that doesn't exist, is refused and the state is unchanged. Use exact arithmetic (integers in the smallest unit, or numerators over a common denominator), never floating point.
4. `score.ts`: flips (a pair of flips counts as one), time in whole seconds passed in by the caller, and stars: gold within 1.5× the minimum number of flips, silver within 2.5×, bronze for finishing. Put the thresholds in one editable config object.
5. `save.ts`: the shape of what the browser will send the server later (seed, bond id, board size, the list of flips, the time), plus a pure `replay(save)` that rebuilds the game from the seed and runs the flips, returning the final state and stars, or an error if any flip is illegal or the game doesn't finish. Do not build the server function or database yet (M.4).
6. Tests next to each file: every bond set builds every board size; the one-partner proof for every bond set × every board size × 200 different seeds; no card side repeats in a way that gives two right partners; the same seed gives the same deck and a different seed a different one; engine happy path, mismatch, refused actions, finish; exact decimal and fraction sums; stars at the edges; replay gives the same result as playing, and a doctored flip list is rejected. A simple bot-free "perfect player" helper in the test file that clears a board in the minimum flips is useful for the star tests.
7. Run the whole test suite and the type check, and make sure `npm run build` still passes.
