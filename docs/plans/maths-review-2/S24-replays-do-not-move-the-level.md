# S24: Same-day replays must not move the level (Pipi, Penguin Pairs, Hop)

**Game:** Pipi, Penguin Pairs, Hop
**What's wrong:** A child can replay the same day's round and the level is worked out again from the new answers. Practice replays can push a child up a level, or change what they get tomorrow.
**What done looks like:** The level changes only at a child's first finish of the day. Replays still save their answers, but the level the child sees does not move.
**Size:** S
**Impact on learning:** High
**Waits for:** nothing

## 1. The problem

Each game works out the level on every finish, not only the first of the day.

- Hop: `shared/hop/server.ts:156` sets `reached = stepFor(withAnswers(facts, answers), stepBefore)` on every finish. `finishChallenge` gives `padChanged` at `:157`. On a replay it is null (`shared/hop/progress.ts:82-85`), but `reached` has already moved.
- Pipi: `shared/pipi/server.ts:157-158` sets `levelBefore` and `reached = levelFor(withAnswers(...))` on every finish. `shellChanged` is null on a same-day finish (`shared/pipi/progress.ts:78-82`).
- Penguin Pairs: `shared/korora/server.ts:156-163` recomputes `levelBefore` and `reached` on every finish. `pebbleChanged` is null on a replay (`shared/korora/progress.ts:87`).
- The next round uses the facts, not the saved level: Hop `makeRound` calls `stepFor(list, opts.reached)` (`shared/hop/round.ts:240-243`), Pipi `levelFor(list, opts.reached)` (`shared/pipi/round.ts:162`), Penguin Pairs `levelFor` (`shared/korora/round.ts:213-216`).

## 2. The rule behind it

- Rule 6: practice replays must not move the level. A level moves on the day's real attempt.

## 3. The change

Do this the same way in each game.

1. Move the level only when the day's first finish happens: when `result.padChanged` (Hop), `result.shellChanged` (Pipi) or `result.pebbleChanged` (Penguin Pairs) is not null. On a replay, `reached` stays `s.reached`.
2. Load and start use the saved `reached` directly. Add an `opts.level` (Hop `opts.step`) to `makeRound` that is used as is when given, so facts from replays cannot change the level shown that day or the next. Keep the current calculation when no saved value exists (new child).
3. Replays still record their answers (facts). Say honestly in a code comment: facts improved on a replay can still count at the next day's first finish.
4. `reached` is already the same number the game would work out live, so no data fix is needed.

No kit part changes. `shared/kit/replay.ts` is not touched.

## 4. Files affected

- Hop: `shared/hop/server.ts`, `shared/hop/round.ts`, tests.
- Pipi: `shared/pipi/server.ts`, `shared/pipi/round.ts`, tests.
- Penguin Pairs: `shared/korora/server.ts`, `shared/korora/round.ts`, tests.
- `supabase/functions/<game>/index.ts` generated by `npm run build:functions`.
- One small PR per game (Hop, Pipi, Penguin Pairs), each on its own branch.

## 5. Database / migration needs

None. `reached` is already saved in each game.

## 6. Test steps

Automated (2 tests per game, within the 8-per-game limit):
1. A replay with all answers right does not change `reached`.
2. The first finish of the day with the same answers does move it.

By playing: finish a round, replay it with perfect answers, and check the next round is the same level.

## 7. Size and impact

S: one condition per game, plus one option on `makeRound`. High: a practice replay can no longer jump a child up.
