# src/kit: shared screens for the games

Rules (docs/plans/GAME-KIT-PLAN.md section 3): no game words in here; a change is its own small branch and PR; a game moves onto a part only when it is next touched, and nothing a child sees may change by accident. docs/kit/README.md (K2) will hold the full catalogue; until it lands, this is the list.

Every picture is SVG, takes a required `label` (the words a screen reader says; never give away an answer still being worked out), and takes colours as props (`colors={{ highlight: 'var(--wk-gold)' }}`) or as CSS variables on a parent (`--kit-highlight`). With neither it uses the text colour (`currentColor`).

- **`TenFrame`**: rows x cols of squares (default 2 x 5). Each square is `filled`, `highlight` (ring and accent), `extra` (own colour, dot inside), `empty` (dashed space) or `faint` (ghost counter). `frameSquares({ filled: 8, highlight: 2 })` builds the list. Lifted from Tūī `art.tsx` and Weka `Pebbles.tsx`, without their painted berries and pebbles.
- **`NumberLine`**: any range (0 to 20, 40 to 50, 0 to 1000), small marks (`step`, `labelEvery`), `landmarks` (the middle, the tens, a rock; `label: null` leaves one unlabelled), `arcs` (jumps above or below, with a label) and `points` (a dot or ring, with a label such as `?`). `lineX` and `lineTicks` give a game the same positions for drawing; `valueAtX` is the other way round (where a tap landed, as a value). A `lens` ({ from, to, step, landmarks, points }) adds a zoomed second line under the first that shows only that gap, joined to it by two dashed guide lines. `onPick(value)` makes the line tappable and reports the value under the tap (on the lens when there is one, unless `pickOn="line"`); the game decides what is close enough. `look: 'arrow'` on a point draws a real down-pointing arrow above the line (tip on the value, label above it) for "what number is at the arrow?". `room` and `roomBelow` reserve height above and below the line so it does not move when arcs or an arrow appear later; the lens takes `arcs`, `room` and `roomBelow` the same way. A `LinePoint` can take a `tone` (`point`, `landmark`, `arc`...) so a guess and a true place can be different colours.
- **`DotPicture`**: dots in a box you size, an optional frame of squares behind them, `mode="groups"` to outline and colour natural groups, `tintGaps` and `ghosts` for the empty squares. `gridDots(rows, cols, w, h, gap)` gives neat rows for arrays. Lifted from Quick looks `PictureSvg.tsx`, minus the die, which stays there.
- **Junior bits (K4)**: `HearAgain` (`<prefix>-button`), `PointingHand` and `pointedLabel` (`<prefix>-hand`), `useGuidedFirstGo(guided, ms)` (`pointing`, `start`, `stop`), `WhatsNext` (the end-of-round panel), `FirstTimeTip` (a helper's tip card, Star Trader's `TipCard` with its words passed in). `voiceLinesSuite(game, allVoiceLines)` is test code in `voiceLinesSuite.ts` (not in the index). Lifted from Weka, Penguin Pairs and Star Trader; Weka uses all but `FirstTimeTip`.
- **Seen kinds (S11)**: `useSeenKinds(initial, save)` returns `{ has(kind), mark(kinds), seenKinds }`. `initial` comes from the server; `mark` updates at once, then calls `save`, and keeps unsent kinds for the next `mark` if saving fails (play is never blocked, nothing shows, nothing is stored in the browser). The server parts are in `shared/kit/seen.ts` (`readKinds`, `mergeSeen`, `kindsFromFacts` to backfill children who have already played, `SeenServices`, `memorySeen`), backed by the `kit_seen` table and the `kit_seen_get` / `kit_seen_mark` functions. Rules for a game that uses it: (1) a kind is marked seen when its demo ends or is skipped, or when the child finishes any go of that kind, so every kind played is remembered even if it has no demo yet; (2) the guided first go marks its own kind when it is finished; (3) kind names are short, lower case and stable (`zoom`, `swap`), never renamed after they ship.
- **Show me first (S12)**: `useKindDemo({ kind, seen, mark, steps, say })` plays a demo the first time a kind of go comes up (`seen` and `mark` come from `useSeenKinds`). `steps` are `{ line, holdMs?, target? }`: each line is said with the game's `say`, then it waits `holdMs` (default 900 ms). It returns `{ playing, step, target, canSkip, skip, replay }`. `canSkip` turns true after 3 seconds; it gives up after 20 in case a voice never ends; when it ends or is skipped it calls `mark([kind])` once. A seen kind does nothing. `DemoBar({ prefix, skipLabel, replayLabel?, canSkip, onSkip, onReplay? })` draws Skip (only when `canSkip`; Escape also skips) in line; the game styles `<prefix>-demo`. The hand is the existing `PointingHand`, drawn by the game inside what it points at. While `playing` the game's choices must not be tappable and no tap may be added to the round: a demo is not an answer. The example must be one the real round cannot ask.

Used by: Weka (the junior bits); the pictures: nothing yet. Next: the new games N1 (`NumberLine`), N3 and N5 (`TenFrame`), N4 (`DotPicture` arrays). Old games stay as they are until an R-plan next touches them.
